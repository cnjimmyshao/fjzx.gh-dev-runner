# 本地轻量接单与会话续接

Status: PARTIALLY_SUPERSEDED

2026-09-23 更新：[ADR 0002](0002-headless-cli-execution.md) 替代本记录中“接入常驻 Harness Web、在原网页观察”的部分。本地增量接单、多执行机、任务会话绑定与不建设全流程编排的决定继续有效。下文保留原决策语境，不再作为 Web 接入的当前要求；当前行为以 `docs/current/` 为准。

依据：维护者确认的项目方向，已在本仓库 Issue #1 记录。本决定说明目标边界，不代表代码或运行环境已经验证。

## 背景

需要在 GitHub 的任务入口启动或继续 Dev 工作，减少人工在工具间转述，并在既有 Harness Web 界面观察。不同项目依赖不同执行环境；一个工具应能分别部署在多台电脑上，而不是每项目复制一套复杂 Workflow。

## 决定

使用独立本地接单工具，约一分钟增量检查明确接入仓库的评论。每台电脑有自己的身份与配置，任务明确指定唯一执行机；以仓库身份和 Issue 编号关联本机会话与工作目录，优先续接原会话。

接单与业务开发分开：工具负责接收、路由和投递，Dev 按目标项目的 Issue 与 AGENTS 工作。接入常驻 Harness 的具体方式先做实际环境验证；不把任意 headless 运行视为 Web 会话续接。

首版不使用 Actions 定时轮询，不搬运旧自动化编排，不建设中央数据库、分布式抢单、自动合并、独立 Review 裁判或复杂会话恢复。精确命令语法、配置与存储格式不在本 ADR 预定。

## 代价与限制

接受轮询延迟和执行机离线时的不可用；需要遵守 GitHub API 的用量限制。机器身份唯一由部署配置负责，不提供多实例自动选主。会话无法恢复或投递结果不明时先报告和核对，不用静默重建掩盖问题。

接单工具仍需要授权检查、去重、单任务写入协调、真实状态与凭证保护；简单不意味着删除实际安全边界。后续只有真实需要且获批时才扩展这些边界。
